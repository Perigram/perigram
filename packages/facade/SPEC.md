# SPEC: Facade fabrication pack

Desired state, owner's words (2026-09-29/30), for the order flow the pack
exists to exercise.

## The composed order process

Everything goes from the graph via established graph means. An uploaded
order table (xlsx workbook or CSV) becomes one org-authored container with
baked cassette-design children, declared sheet materials, and one nesting
run per material — as an authored process graph over established species:
declared projections (`rows`), `collection.join`, `cts.construct` in the
declared `bake` mode, `cts.field`, and the pure `nesting.solve` service.
No parallel ad-hoc import pipeline exists: no table-import surface, no
batch construction transport. A node or operation is invented only when
composition is impossible without it.

## Cassette is a file type

Cassette rides the generic per-class instance service (SPEC §13) like
every pack file type: no bespoke Mongo collection, no service bridge, no
adapter shims. The OCCS template document is the payload — the §3 blob
home (GridFS) — and the one home: no inline `data.definition` twin. The
geometry revision chain is the generic payload-replacement revision
machinery over the declared `geometry` scope. STANDARD templates keep
their extracted geometry (`polygonParts`, `layerData`, `mapping`) as
declared fields computed at import; PARAMETRIC templates keep `parameters`
as a declared field.
