# Nesting System Analysis

**Date:** 2025-11-26  
**Status:** Worker incompatible with new batch/cassette system

---

## Problem Summary

The nesting worker expects data from the **old project-based system** but the new **batch/cassette system** stores data differently, making nesting impossible.

---

## Current Architecture

### Old System (Project-Based) ✅ Working
```
User uploads DXF → server/core/project/dxf.js
    ↓
Saves to user_dxf_files collection with processingStatus='pending'
    ↓
workers/fileprocessing/main.py picks up job
    ↓
Processes DXF → generates polygonParts (coordinates + handles)
    ↓
Saves back to user_dxf_files with polygonParts array
    ↓
User creates nesting job → workers/nesting/main.py
    ↓
Reads user_dxf_files → finds polygonParts → runs lbf nesting
    ↓
Saves result DXF/SVG files to GridFS
```

### New System (Batch-Based) ❌ Broken
```
User uploads cassette → server/features/cassettes/service.js
    ↓
Saves DXF to GridFS (cassettes bucket)
Creates cassettes collection doc with layerMapping
    ↓
❌ NO polygon processing happens
    ↓
User creates batch with cassette entries
    ↓
POST /api/batch/:id/nest creates nesting_jobs doc
    ↓
workers/nesting/main.py picks up job
    ↓
❌ Tries to read user_dxf_files collection
❌ Can't find polygonParts data
❌ Nesting fails
```

## Data Structure Comparison

### Old: user_dxf_files collection
```javascript
{
  _id: ObjectId,
  slug: "file-abc123.dxf",
  name: "my-part.dxf",
  ownerId: "google:12345",
  projectSlug: "project-xyz",
  processingStatus: "done",
  isDxfCopyExist: true,
  polygonParts: [  // ← Generated by fileprocessing worker
    {
      coordinates: [[x1,y1], [x2,y2], ...],
      handles: ["1A3", "1B5", ...],  // DXF entity handles
      width: 500.0,
      height: 300.0
    }
  ]
}
```

### New: cassettes collection
```javascript
{
  _id: ObjectId,
  slug: "cassette-abc123",
  name: "My Cassette",
  userId: "google:12345",
  dxfId: ObjectId,  // GridFS file ID
  svgId: null,
  layerMapping: {
    cut: ["Layer1", "Layer2"],
    bend: ["Layer3"],
    frame: ["Layer4"],
    dimensions: []
  },
  parameters: ["A", "B", "C"],
  options: {
    allowRotation: true,
    negativeOffset: 0
  },
  processingStatus: "done"
  // ❌ NO polygonParts field
}
```

## Worker Code Issues

### workers/nesting/core/main.py:53
```python
def convert_files_to_input_items(files, space):
    # ...
    for file in files:
        file_slug = file.get("slug")
        
        # ❌ This collection doesn't exist in new system
        user_dxf_file = db["user_dxf_files"].find_one({"slug": file_slug})
        
        # ❌ This field doesn't exist
        plogonParts = user_dxf_file.get("polygonParts")
```

### server/api/batch/[id]/nest.post.js:36
```javascript
// Maps cassette to file slug for worker
const files = batch.entries.map((entry, index) => {
  const cassette = cassettes[index];
  return {
    slug: cassette.dxfId || cassette.slug,  // ❌ Wrong format
    name: cassette.name,
    count: entry.quantity
  };
});
```

**Problem:** Worker expects `slug` to match filename in `user_dxf_files`, but cassettes use different storage.

## Solutions

### Option 1: Dual System (Quick Fix) ⏱️ 2-4 hours
Keep both systems running. When cassette is uploaded, also create `user_dxf_files` entry.

**Pros:**
- Minimal worker changes
- Fast to implement
- Maintains backward compatibility

**Cons:**
- Data duplication
- Confusing architecture
- Technical debt

**Implementation:**
1. Modify `server/features/cassettes/service.js::upload()`
2. After saving to `cassettes`, also create `user_dxf_files` entry
3. Trigger fileprocessing worker to generate polygonParts
4. Update nest.post.js to use correct slug

### Option 2: Rewrite Worker for New System (Proper Fix) ⏱️ 8-12 hours
Update worker to read directly from `cassettes` collection and GridFS.

**Pros:**
- Clean architecture
- No data duplication
- Future-proof

**Cons:**
- More complex changes
- Requires Python work
- Higher risk

**Implementation:**
1. Modify `workers/nesting/core/main.py`
   - Change `convert_files_to_input_items()` to read from `cassettes`
   - Generate polygon parts on-the-fly from GridFS DXF
   - Use existing `build_geometry()` logic
2. Modify `workers/nesting/core/main.py::get_entities_from_dxf_file()`
   - Read from GridFS cassettes bucket instead of valid_dxf_bucket
   - Use cassette.dxfId to fetch file
3. Update batch nest endpoint to pass correct file references

### Option 3: Cassette Pre-processing (Hybrid) ⏱️ 4-6 hours
Add polygon processing when cassette is created, store in cassettes collection.

**Pros:**
- One-time processing
- Fast nesting execution
- Clean separation

**Cons:**
- Cassette upload becomes async again
- Need to update cassettes schema
- Still need worker integration

**Implementation:**
1. Add `polygonParts` field to cassettes schema
2. Create processing job when cassette uploaded
3. Reuse fileprocessing worker logic for cassettes
4. Update nesting worker to read from cassettes

---

## Recommended Approach

**Option 3 (Cassette Pre-processing)** - Best balance of clean architecture and compatibility.

### Step-by-step:

1. **Update cassettes schema** (docs/specs/data-schema.md)
   ```typescript
   interface CassetteTemplate {
     // ... existing fields
     polygonParts?: Array<{
       coordinates: [number, number][];
       handles: string[];
       width: number;
       height: number;
     }>;
   }
   ```

2. **Create cassette processing job**
   - Copy fileprocessing worker logic
   - Trigger when cassette uploaded
   - Generate polygonParts from cassette DXF in GridFS
   - Update cassettes doc with polygonParts

3. **Update nesting worker**
   ```python
   # workers/nesting/core/main.py
   def convert_files_to_input_items(files, space):
       for file in files:
           cassette_id = file.get("cassetteId")
           cassette = db["cassettes"].find_one({"_id": cassette_id})
           polygonParts = cassette.get("polygonParts")
           # ... rest of logic
   ```

4. **Update nest endpoint**
   ```javascript
   // server/api/batch/[id]/nest.post.js
   const files = batch.entries.map((entry) => ({
       cassetteId: entry.cassetteTemplateId,
       count: entry.quantity
   }));
   ```
