# COMPONENT: Nesting Runs

Stores the digital solutions generated by the nesting algorithms.

## v24 Architecture
- **Digital Bridge**: Connects a `Queue` intent to a specific material layout.
- **Lineage**: Cumulative trace inheriting from Project and Queue (`lineage.runId` used for child artifacts).
- **Status**: Governed by `NestingRunMachine` (NESTING -> COMPLETE | ERROR | CHOSEN).
- **UI Components**: 
  - `NestingRunCard`: Supports `card`, `inline`, and `compact` variants. Holds `ArtifactCard` components.
  - Smart Actions: `Find in Warehouse`, `Create Requisition` (permission-aware).

## Key Workflows
1. **Proposal**: Created automatically by the `Nesting Processor` after algorithm completion.
2. **Review**: Users evaluate efficiency and layout using standardized artifacts (DXF, PDF).
3. **Acceptance**: Triggers `CHOSEN` state and enables physical material reservation.
4. **Physical Bridge**: Transition from `VIRTUAL` mode to `WAREHOUSE` via material matching action.

## Data Structure
```typescript
{
  runNumber: Number,
  materialMode: Enum(VIRTUAL, WAREHOUSE),
  params: { width, height, space, sheetCount, inventoryItems?, sheet_polygon? },
  origin: StatusBlock,
  status: StatusBlock,
  lineage: { organizationId, projectId, queueId },
  layoutCount: Number,
  placedCount: Number,
  utilization: Number,
  error: String,
  requestedArtifacts: Array<String>
}
```
