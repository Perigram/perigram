# COMPONENT: Server Features (v24 Standardized)

This directory contains the core business logic modules. All modules are refactored to follow the v24 Block Architecture and Service-Repository pattern.

## Core Design Patterns (v24)
- **Standardized Blocks:** Every entity MUST use `identity`, `status`, `origin`, and `lineage`.
- **Cumulative Lineage:** Ancestry is flat and inherited, allowing O(1) reverse lookups across any depth.
- **State Machines:** Lifecycle logic is removed from features and centralized in `server/core/machines/`.
- **Service-Repository:** Repositories handle raw DB access; Services handle logic, permissions, and cross-module calls.

## Core Modules
- **[projects](./projects/):** Root of the production tree. Contains `summary` aggregates.
- **[queues](./queues/):** Production batches (nesting jobs) linking digital designs to physical material.
- **[cassettes](./cassettes/):** Master templates for manufacturing items.
- **[nesting-runs](./nesting-runs/):** Specific solutions generated by the nesting worker.
- **[material-piles](./material-piles/):** Inventory units (formerly batches) representing physical stock.
- **[sheets](./sheets/):** Individual work units, both digital designs and physical material.
- **[cassette-instances](./cassette-instances/):** The "Digital Twin" of every manufactured part.
- **[requisitions](./requisitions/):** Procurement workflow between contractors and manufacturers.
- **[artifacts](./artifacts/):** File management (DXF, SVG, PDF) linked to the lineage tree.

## API & Interaction
Modules interact via services. Cross-module database access is strictly forbidden. 
Permissions are enforced using `server/utils/permissions.js` which validates the `lineage` block against user memberships.
