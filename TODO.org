** Public contracts and architecture

*** Entity relations and containment

    - Extend =@cutkit/core= with one canonical =EntityRef= value:
      ={ type, id, revisionId? }=. The optional revision ID identifies an
      immutable =entity_revision= for that same source entity. Runtime results,
      process ports, relations, and provenance use this exact value shape.
    - Add canonical =relations= and =provenance= entity blocks. A relation entry
      contains one =EntityRef= or a cardinality-declared list of =EntityRef=
      values. A provenance entry contains a =source: EntityRef= plus immutable
      derivation facts such as scope, revision number, content hash, source
      status, and parameters.
    - Use =relations= for non-owning links such as a project using a cassette
      library. Relations must not affect ownership, access ancestry, top-level
      list placement, or breadcrumbs.
    - Use =provenance= for immutable derivation evidence and for an optional
      exact immediate-parent revision captured at child creation. Provenance is
      never an editable relation and never changes containment or access.
    - Reserve =lineage= for containment and access ancestry.
    - Replace =cncSummaries= as the implicit parent/child registry with explicit
      containment declarations containing parent type, child type, lineage key,
      and optional aggregate policy. Keep summary aggregation separate.
    - Add process-authored relation declarations to entity profiles so relation
      sockets, traversal, persistence, and display derive from one contract.

*** Revision-aware references

    - Keep scalar =lineage.<parentType>Id= fields for access and queries.
    - When child creation pins the immediate parent revision, store
      =provenance.parent.source = { type, id, revisionId }=. The =type= and =id=
      must match the declared containment parent and the scalar lineage parent
      ID. Never add revision keys to =lineage= and never encode composite IDs
      with delimiters.
    - Ordinary relations may independently pin a revision through the same
      optional =EntityRef.revisionId= field.
    - No revision means follow the entity; a revision means reproduce the
      relationship against that exact immutable snapshot.
    - Migrate cassette-design derivation from =data.derivedFrom= to
      =provenance.derivedFrom= and entity-revision source metadata from sibling
      =entityType/entityId= fields to =data.source: { type, id }=. Do not retain
      dual-read compatibility paths after migration.

*** Machine, tool, material, and queue settings

    - Add a =machine= entity with public system records and organization-owned
      records.
    - Seed a system default with a 3000 x 1500 mm working area and zero uniform
      sheet-boundary offset.
    - Replace queue nesting spacing/settings with explicit =machineId=,
      =toolProfileId=, material mode/source references, and virtual material
      width, length, and thickness.
    - The selected tool's =kerf= is the exact nesting and manual-editor item
      gap. Remove the independent spacing override and do not retain a fallback.
    - Nesting runs store immutable serialized machine, tool, and material
      snapshots. The strict worker payload is derived from those snapshots.
    - Reserve ordinary OCCS parameter =T= for selected material thickness.

      queue item editing cannot override it independently.

*** Process actions
